# Device tree and overlays in Yocto (meta-raspberrypi)

Status: complete (overlay shipping on Raspberry Pi)
Verified: kernel=rpi-6.6.y (SRCREV e442e5c = 6.6.63, the pin used by meta-raspberrypi scarthgap; head 6.6.78); yocto=scarthgap (poky 3a3d07f + meta-raspberrypi 6ca1f75, parsed with bitbake -p, NOT built); buildroot=n/a

## 1. When to use / not to use

Use to get a DTB or overlay into the boot partition and enabled. Not for
writing DT content (`elinux-kernel`), and not for U-Boot-based boot flows
(`RPI_USE_U_BOOT`), which load DT differently and are not covered.

## 2. Conceptual model

- The kernel recipe builds everything in `KERNEL_DEVICETREE`; for this BSP it
  is `RPI_KERNEL_DEVICETREE` (board DTBs) plus `RPI_KERNEL_DEVICETREE_OVERLAYS`
  (`overlays/*.dtbo`). Boot files are deployed from that list.
- The firmware applies an overlay only if its `.dtbo` is in the boot
  partition **and** `config.txt` has `dtoverlay=<name>`.
- `config.txt` is generated by `rpi-config`; `RPI_EXTRA_CONFIG` is appended
  verbatim (verified in `rpi-config_git.bb`).
- The overlay *source* must also be built by the kernel: it comes from your
  kernel patch (`overlays/<name>-overlay.dts` + entry in
  `overlays/Makefile`).

## 3. API and kernel versions

Verified by `bitbake -e` for `raspberrypi0-2w-64`: `RPI_KERNEL_DEVICETREE` is
`broadcom/bcm2710-rpi-zero-2.dtb`. The default overlay list has `imx219`
but not `ov5647`, and not custom overlays. `rpi-config` has dedicated switches
only for `imx219` and `imx708` (the `imx477` one is commented out); any other sensor needs `RPI_EXTRA_CONFIG`.

## 4. Device Tree binding

Defined by the driver patch; overlay labels need the base DTB built with
symbols (`-@`, `KERNEL_DTC_FLAGS += "-@ -H epapr"` in the 6.6 recipe).

## 5. Minimal example

`templates/local.conf.snippet`:

```
RPI_KERNEL_DEVICETREE_OVERLAYS:append = " overlays/mycam.dtbo"
RPI_EXTRA_CONFIG = "\ndtoverlay=mycam\n"
```
Verified: `bitbake -e virtual/kernel` shows `overlays/mycam.dtbo` in
`KERNEL_DEVICETREE`; `bitbake -e rpi-config` shows
`RPI_EXTRA_CONFIG="\ndtoverlay=mycam\n"`.

## 6. Common pitfalls

- Overlay in `KERNEL_DEVICETREE` but the kernel patch does not build it
  (or the reverse): build error or missing `.dtbo` on the boot partition.
- `RPI_EXTRA_CONFIG` assigned with `=` in a later file overriding another
  layer's value: use `:append` with a leading newline when composing.
- Setting `RPI_KERNEL_DEVICETREE_OVERLAYS` only in a kernel bbappend: other
  recipes (boot files, wic) do not see it. Set it globally.
- Machine-specific overlay list applied to all machines: use machine
  overrides (`:raspberrypi0-2w-64`).
- Both the stock `ov5647` overlay and your own enabled: two nodes, one I2C
  address.

## 7. How to test

`scripts/check_layer.sh --overlay <name>.dtbo` (parse-time). After building:
`ls <deploy>/*/overlays/<name>.dtbo`, inspect `config.txt` in the image,
and on target `ls /proc/device-tree/soc/i2c0mux/` (`elinux-testing`).
